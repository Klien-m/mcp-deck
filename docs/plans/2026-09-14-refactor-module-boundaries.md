# 模块边界重构实施计划

**目标：** 基于最新 `origin/master`（`d874ad0`）整理前后端职责，保留现有界面、IPC 操作和持久化格式。

**设计：** 延续现有 React / Tauri / Rust 分层。前端将功能状态交给服务详情和业务弹窗，工作区 Hook 负责快照与写操作协调；后端分离计划计算、事务恢复及适配器职责，保留 Engine 和 adapters 公开入口。采用小范围模块提取，不引入状态管理库、插件框架或通用仓储层。

**约束：** 保留完整差异与脱敏差异共用同一预览计划的最新修复，以及 Codex 独立 TOML 服务表的输出。保留备份、外部修改检测、失败恢复和提交顺序。只调整涉及部分，不全局格式化。

## 1. IPC 契约

- 修改 `src/api.ts`、`src/types.ts`，建立命令参数和返回类型映射。
- 收紧变更 action、历史 status 的前端类型，迁移调用点，保持 Rust 序列化字段兼容。
- 将 `save_export` 的路径保护和写入放入 Engine，由 `src-tauri/src/lib.rs` 转发。
- 验证：TypeScript 正确调用通过；缺参数、错误参数及不存在的命令应被编译器拒绝；导出路径保护使用隔离目录测试。

## 2. 前端功能边界

- 修改 `src/App.tsx`，增加 `src/hooks/useWorkspace.ts` 和 `src/features/` 下的详情及弹窗组件。
- ServiceDetail 按服务管理检查状态，防止筛选后沿用旧服务的检查；ExportDialog 按当前请求管理导出结果。
- 拆出发现、导入、同步预览、工具管理和历史弹窗，保留公共写操作协调，完整差异开关继续只切换本地显示。
- 第一阶段保持现有 CSS 类和界面结构；第二阶段按下述职责整理样式归属。
- 验证：类型检查、生产构建；隔离数据下检查服务切换、发现选择、导出切换、预览切换和弹窗操作。

## 3. 引擎计划与事务

- 将 `src-tauri/src/engine.rs` 整理为 `engine/` 模块，保留现有公开方法和类型的访问路径。
- planner 使用工作区及已读取的目标快照计算原始差异、文件计划和阻断原因；Engine 管理读取、计划缓存与展示脱敏。
- transaction 统一维护 journal、执行、回滚、恢复及绑定更新；工作区提交仍是事务是否完成的依据。
- 只在边界需要时提取领域辅助函数，不将不同含义的 binding 判断强行合并。
- 验证：现有 Rust 核心测试；补充已提交工作区的 prepared 日志恢复、工作区提交失败回滚等协议场景。

## 4. 适配器分层

- 将 `src-tauri/src/adapters.rs` 拆为 `adapters/mod.rs`、注册信息、字段转换和文档编辑模块。
- 保留 `registry/get/default_targets/parse/decode/encode/patch` 的公开路径。
- 保留全部现有 JSONC/TOML、原生字段和只读拒绝语义，不为每个客户端建立独立 trait。
- 验证：现有适配器矩阵、重复键、原文保留及 Codex TOML 回归测试。

## 5. 集成验收

- 执行 `npm run build`、`npm test`、`npm run check`，Cargo 使用项目已有离线缓存。
- 评审 diff，确认没有无关格式修改，检查前后端契约以及最新两项修复没有退回。
- 更新 README 结构说明，记录验证结果和任何未完成的检查。

## 6. 第二阶段：完成职责拆分

用户确认继续处理剩余部分，采用以下边界，保持业务行为与 IPC 契约不变：

- 前端按 services / targets / transfer / sync 组织功能；每个独立弹窗和编辑器拥有自己的文件。
- 主界面提取导航、服务列表、启动页及空状态；App 仅保留界面状态和装配，弹窗装配独立。
- 收窄组件参数，不传递整个 Snapshot 或通用命令执行器。所有写操作（包括编辑、目标路径、导出文件）统一由 useWorkspace 协调忙碌状态、错误和刷新。
- Rust Engine 保留公开入口和原子工作区提交；服务变更、发现导入、目标路径、导出和诊断按用例提取。同步计划缓存和事务协调单独归属同步模块。
- 样式按基础控件、布局及功能拆分；保留选择器、声明及必要的级联顺序，通过程序比较拆分前后规则验证行为不变。
- 验证构建、Clippy、Rust 回归及隔离桌面流程；补充批量导入失败的原子性、路径约束和预览失效等跨边界测试。
