# MCP Deck 稳定性与跨平台配置实施计划

**Goal:** 修复保存结果误报、待移除项不可见、版本号固定的问题，增强同步状态与静态诊断，并验证 Windows/Linux 默认路径和发布前回归。

**Architecture:** 保留统一服务模型和现有事务写入；显示状态与写入结果分开管理。诊断保持只读，路径解析通过可注入的平台和目录参数验证，自动化检查覆盖三个桌面系统。

**Tech Stack:** React / TypeScript / Vitest；Rust / Cargo；Tauri 2；GitHub Actions。

## 分工与步骤

1. 主 agent：`src/hooks/useWorkspace.ts` 分离已提交结果与刷新失败，失效状态只重试读取；新增 Hook 回归测试。`src/App.tsx` 装配持续刷新提示、撤销入口及实际安装包版本。
2. 同步状态 agent：服务列表保留待移除项并提供撤销；区分待新增、更新、移除、配置读取问题与文件对齐；预览明确动作和目标，完整差异切换保持纯显示；补充组件测试。
3. 静态诊断 agent：执行权限、PATH / PATHEXT、工作目录与字段检查；返回结构化可操作提示并渲染；使用临时目录测试，不启动 MCP 或访问网络。
4. 平台路径 agent：Windows APPDATA、Linux XDG、macOS Application Support 及工具覆盖目录；隔离 home 不读取真实自定义目录；仅迁移无绑定的可确认旧默认值；补充纯函数平台矩阵与原生路径测试。
5. 主 agent：加入 pull request / 分支验证工作流和发布前回归，保留标签版本来源与旧标签重建策略；同步中英文文档。
6. 集成：运行 UI、Rust、版本脚本测试及 TypeScript / Clippy / build；检查 UI 和 diff，只改动相关部分。无需写入用户 Agent 的真实配置或发布新版本。

## 验收

- 后端写入成功而刷新失败时返回成功 ID，界面不诱导重复写入；刷新恢复之前不使用旧计划执行变更。
- 待移除服务可从待应用视图找到并撤销，应用成功后的历史删除项不永久占据待应用列表。
- 配置对齐不等同于客户端已加载；静态诊断不伪装连接测试。
- 原生版本号取自安装包；读取失败有明确占位，不显示硬编码旧版本。
- Windows/Linux 无 macOS 默认路径；显式隔离环境不会访问真实工具目录。
- 新测试在本机通过，并由三平台 CI 自动执行；未在本机运行的平台不声称已实机验收。
