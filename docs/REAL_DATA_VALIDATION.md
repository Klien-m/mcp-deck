# 本机真实配置验证

日期：2026-09-14。分支：`req/kouxinxin/2026/09/real-data-validation`。

本轮按用户选择验证配置读取、发现、纳入管理、文本导入和同步预览。使用产品现有 Rust 配置引擎，在项目 `.local-dev/` 下创建全新的临时工作区；未运行 MCP 服务或联网检测，也未调用应用、恢复操作。

## 实机结果

检查 12 类工具的默认用户级路径，发现 10 个配置文件，共 18 条服务配置。其中 17 条成功纳入临时服务库，纳入后没有产生配置差异。原文件检测前后的 SHA-256 内容指纹一致，包括空文件和不存在的目标文件。临时工作区及其中导入的配置在检测结束后删除。

| 工具 | 发现条目 | 可纳入管理 | 文本导入 / 编辑预览 |
| --- | ---: | ---: | --- |

具体限制：

- Cursor 的一条配置使用 `type: process`，当前适配器不支持该类型。发现流程可以选择其余 11 条；整文件文本导入保持全有或全无，拒绝后临时服务库没有部分导入。
- Windsurf 与 Kiro 的现有条目带有 `cwd`。原始配置可以纳入管理并原样保留，但当前适配器未声明 `cwd` 支持，修改后重写会被拦截。本轮没有删除或转换该字段。
- VS Code 的空文件没有被自动补写。应由用户在宿主工具中确认配置位置与内容。

## 可重复运行

```bash
npm run validate:local
npm run validate:local -- --home /absolute/fixture-home
```

如使用本项目已有 Cargo 缓存：

```bash
CARGO_HOME="$PWD/.local-dev/cargo-home" npm run validate:local
```

输出只包含工具标识、条目数量和结果，不包含服务名称、路径、地址、命令参数或凭据。运行时仍会在临时工作区保存真实配置，以验证实际持久化和导入流程；临时目录权限为 0700，配置文件为 0600，运行结束后删除。详细 JSON 报告可自行重定向到 `.local-dev/`，该目录不会提交到 Git。

`invariantsPassed: true` 表示纳入后无多余差异、编辑预览符合当前适配器约束、导入保持原子性且不自动分配、源文件内容未变化。字段限制和解析失败单独列出，不代表相应服务可运行或已通过客户端认证。退出码 2 表示这些不变量检查失败；退出码 1 表示验证未完成。

## 验证记录

- 原有隔离样例：9 条配置，纳入、导入及更新预览通过。
- 本机真实配置：17 条可管理配置，不变量检查通过；已记录上述限制。
- 专项样例：未知类型与正常条目混合导入、`cwd` 写入限制、空文件拒绝、源文件内容一致性通过。
- `cargo test --no-default-features`：15 项核心测试通过。
- `cargo clippy --all-targets -- -D warnings`：通过。

本轮没有修改 UI、配置方言或真实配置文件。该结果不覆盖 MCP 握手、认证、工具列表和业务工具调用。
